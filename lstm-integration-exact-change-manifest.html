2c. NEW backend/ml/dam/train_dam_lstm.py

Purpose: standalone training script you run once.

Exact behaviour:
  • Reads both CSVs from backend/ml/data/dam/; prioritises dam_lstm_dataset.csv (the pre-prepared one); uses dam_simulated_dataset.csv as supplementary if needed.
  • Parses timestamp column; sorts chronologically; validates water_level_cm and rain_detected are present and numeric.
  • Applies a 70/15/15 chronological split (no random shuffle — time-ordered).
  • Builds sliding windows of exactly 60 steps × 2 features (water_level_cm, rain_detected), one-minute sampling interval assumed.
  • Regression targets per window: water_level_next_15min (step+15), water_level_next_30min (step+30).
  • Fits a MinMaxScaler on the two input features using training windows only; never touches val/test data before transform.
  • LSTM architecture: Input(60,2) → LSTM(64, return_sequences=True) → Dropout(0.2) → LSTM(32) → Dropout(0.2) → Dense(16, relu) → Dense(2, linear). Compiled with Adam, loss=MSE.
  • Trains up to 100 epochs; EarlyStopping(patience=10, restore_best_weights=True) on val_loss.
  • Computes MAE and RMSE on test set for both outputs (+15 min, +30 min).
  • Computes persistence baseline (last known value = prediction) MAE/RMSE for comparison.
  • Saves artifacts to backend/ml/models/dam/:
    • dam_lstm_simulated_v1.keras — the trained model
    • dam_scaler.pkl — the fitted MinMaxScaler
    • dam_model_meta.json — window_len=60, features, thresholds, training_source="SIMULATED", split sizes, MAE/RMSE, baseline MAE/RMSE, timestamp
  • Does not overwrite any file under backend/ml/models/ (Stage 3 models).
  • Prints a clear notice: "WARNING: This model is trained on simulated data. Do not claim real-world accuracy."

2d. NEW backend/ml/dam/live_buffer.py

Purpose: thread-safe, in-memory rolling window that feeds the predictor.

Exact behaviour:
  • Class DamLiveBuffer with a threading.Lock around all mutations.
  • Holds a deque(maxlen=60) of one-minute aggregated buckets: {"minute": datetime, "water_level_cm": float, "rain_detected": float}.
  • push(water_level_m: float, rainfall: float, recorded_at: datetime) — called from the sensor ingest hook. Converts water_level_m → cm (×100). Maps rainfall (0.0/1.0) directly. Aggregates into the current minute bucket (mean water_level_cm, max rain_detected). Creates a new bucket when the minute changes.
  • bootstrap(db: Session) — called once at app startup. Queries the last 60 minutes of FloodData rows, aggregates by minute, pre-fills the deque. If fewer than 60 minutes exist, fills with what is available; get_window() will indicate insufficient data until the buffer is full.
  • get_window() — returns (numpy_array_60x2, is_ready: bool, minutes_available: int). is_ready is True only when the deque has exactly 60 valid buckets. The array columns are [water_level_cm, rain_detected] in time order (oldest first).
  • Module-level singleton: dam_buffer = DamLiveBuffer() imported by both the route and the sensor hook.
  • No I/O other than the one startup DB query; never reads from or writes to any file.

2e. NEW backend/ml/dam/predictor.py

Purpose: loads model artifacts once; runs inference on demand.

Exact behaviour:
  • Lazy-loads dam_lstm_simulated_v1.keras and dam_scaler.pkl at first call; caches them in module-level variables.
  • If model files do not exist, returns a structured "not_trained" error response — never raises an exception that would crash the API.
  • get_dam_prediction():
    1. Calls dam_buffer.get_window().
    2. If not ready → returns {"available": false, "reason": "Collecting sensor history ({n}/60 minutes)"}.
    3. Scales the 60×2 window with the loaded scaler (transform only, never fit).
    4. Reshapes to (1, 60, 2); runs model.predict().
    5. Inverse-transforms the two output values back to cm.
    6. Computes trend: compares predicted +15 min value against current (last bucket) water_level_cm. Rising / Falling / Stable (±0.5 cm threshold).
    7. Applies dam thresholds to the predicted values: Normal ≤5.0 cm, Warning >5.0–7.5 cm, Critical >7.5 cm.
    8. Returns: {"available": true, "current_water_level_cm": float, "predicted_15min_cm": float, "predicted_30min_cm": float, "trend": "rising|falling|stable", "forecast_risk": "normal|warning|critical", "prediction_timestamp": ISO-string, "training_source": "SIMULATED", "minutes_in_buffer": int, "thresholds": {"normal_max_cm": 5.0, "warning_max_cm": 7.5}}
